## 3. Bug 列表

### P1（影响核心流程，必须修复）

**BUG-01｜大厅-注册｜注册失败无任何反馈**
- 复现：注册页填 3 位密码（或重复用户名）→ 提交
- 预期：页面显示「密码至少 6 位」/「用户名已存在」
- 实际：按钮无反应，无任何提示（后端 400，错误仅在 `X-Error-Message` 响应头，body 为空）
- 根因：后端错误统一走 header 传递（`httpresp` 空 body 设计），前端 `Register.vue` 未读取该 header 也未展示任何错误
- 建议：后端校验错误返回 JSON body（保持 header 兼容）；前端注册/登录失败展示明确原因；密码框加 `minlength=6` 前置校验
- 截图：无（页面无任何可见变化，这本身就是缺陷）

**BUG-02｜管理后台-游戏｜编辑游戏无法保存**
- 复现：游戏列表点「编辑」→ 开发商下拉「无数据」且必填 → 保存被「请选择开发商」阻塞
- 预期：编辑对话框回填开发商；无开发商时下拉至少能列出全部开发商
- 实际：API `GET /api/admin/game/:id` 正常返回 `developerId=1`，但编辑对话框的下拉 option 未加载（新建对话框同一下拉正常）
- 影响：**所有已存在游戏的基础信息编辑功能 100% 被阻塞**
- 建议：检查 `Game.vue` 编辑分支的 developer option 加载时序（openEdit 未拉取/晚于 dialog 渲染）

**BUG-03｜部署｜前端镜像构建必然失败（两处）**
- 复现：`docker compose -f deploy/docker-compose.yml up --build`
- 实际：
  1. `Dockerfile.frontend-lobby`：monorepo 依赖 `@game-platform/frontend-sdk: file:../../sdks/game-frontend-sdk` 未 COPY 进镜像，`npm ci` 报 `Missing target in lock file`；且 `WORKDIR /app` 层级过浅导致相对路径越界（arborist 归一化错乱，报错极具误导性）
  2. `Dockerfile.frontend-admin` / `lobby`：源码 `import '../../../shared/httpError'`，`frontend/shared` 目录未 COPY，`vue-tsc` 编译失败
  3. 基础镜像 `node:22-alpine`（npm 10.9.8）与仓库 lockfile（npm 11 生成）存在 `extraneous` 解析崩溃
- 影响：CI/CD 与新环境部署直接不可用
- 建议修复（本次测试已在本地验证可行，见 `git diff deploy/`）：
  - WORKDIR 改为 `/build/frontend/lobby`，`COPY sdks/game-frontend-sdk /build/sdks/game-frontend-sdk`
  - 两个前端 Dockerfile 均 `COPY frontend/shared /build/frontend/shared`
  - 基础镜像升 `node:24-alpine`（与 lockfile 生成器版本对齐）
  - 另建议：仓库根补 `.dockerignore`（排除 node_modules/dist），当前构建上下文携带全部依赖目录，体积大、速度慢

### P2（严重影响体验）

**BUG-04｜管理后台-游戏｜游戏名称无重复校验**：同名「幸运老虎机」可重复创建（前后端均不拦截）。大厅将出现不可区分的同名游戏。建议：同开发商下 title 唯一约束 + 前端预检提示。

**BUG-05｜后端-游戏｜超长字段 500 无响应体**：300 字标题 PUT 返回 `500` + 空 body（DB 长度约束错误直接透传）。建议：请求体加长度/格式校验返回 400，全局 recover 捕获后给结构化错误。

**BUG-06｜管理后台-审核｜待审列表缺游戏标识**：游戏名称列 `--`、开发商列空，审核员无法辨识在审对象（只有游戏 ID 和版本号）。建议：pending 列表 join game/developer 表回显。

**BUG-07｜游戏-网络｜断网零感知**：Offline 后 UI 仍「已连接」；spin 乐观动画照跑、请求静默丢失、无错误提示；恢复后也无「已重连」反馈。建议：SDK 监听 `close/error` 更新连接状态并禁用 SPIN，超时提示；断线重连成功后重新拉取余额。

**BUG-08｜游戏-余额｜余额不足提示与余额刷新缺失**：引擎正确拦截不扣款，但「余额不足」提示未可见展示（转瞬即逝或未渲染），余额显示停留在旧值直至下一次游戏事件。建议：`slot:error` 渲染持久错误条并主动请求余额刷新。

**BUG-09｜大厅-性能｜首屏三接口串行**：`/profile(732ms) → /category → /gameList` 串行关键链 761ms。category/gameList 为公开接口可并行；本地环境 profile 鉴权路径 732ms 偏高（建议查 JWT 校验+DB/Redis 往返）。生产构建后模块链会消失，但 API 串行与 profile 慢的问题仍在。

### P3（优化建议）

**BUG-10｜时间显示未格式化**：后台表格/详情直接渲染 `2026-08-16T23:46:54+08:00`。建议统一 `YYYY-MM-DD HH:mm` 过滤器。
**BUG-11｜错误文案未本地化**：登录失败显示 `unauthorized: invalid credentials` 原文。
**BUG-12｜min/max 静默改写**：`minPlayer=50,maxPlayer=10` 被后端改为 `50/50` 且 200 无提示。建议 400 拒绝或至少响应中体现修正。
**BUG-13｜调账后游戏内余额不同步**：管理端调账无推送，游戏内需刷新才见新余额。建议余额变更广播或轮询。
**BUG-14｜审核页前端 URL 指向内网地址**：`http://127.0.0.1:9000/...`（storage PUBLIC_BASE_URL 配置问题，生产需配置对外的 CDN 域名，否则玩家 iframe 加载失败）。

### 环境问题记录（非产品缺陷）

- Docker Hub 在当前网络不可达，需经镜像源拉取基础镜像（postgres/redis/golang/node/nginx 均通过 `docker.1ms.run` 获取）。
- alpine `apk` 默认源不可达，已在 6 个 Dockerfile 中切换阿里云源（见 git diff）。

## 4. 安全测试结论（全部通过 ✅）

| 攻击面 | 结果 |
|---|---|
| 匿名访问受保护 API（游戏详情/profile） | 401 |
| 伪造 JWT / 截断签名 | 401 |
| 玩家 token 调 admin API（身份域隔离） | 401 |
| WS ticket 匿名/伪造获取 | 401 |
| WS ticket 重放（单次使用） | 第二次 401 |
| 参数篡改（负 bet/超大 bet/字符串 bet/非法动作） | **余额零变动**（引擎+钱包双重防线） |
| 错误凭据响应一致性 | 不泄露账号存在性 |
| 登录暴破 | 错误凭据统一文案 + LoginThrottle 限流存在 |
| 玩家 token 不进 iframe（postMessage 桥 + 一次性 ticket 架构） | 验证有效，被攻破的游戏包最多拿到一次性 ticket |

## 5. 缺失功能分析（对标成熟 Online Game 产品）

**玩家体验**
- 无游戏收藏、无「最近玩过」
- 大厅一次性拉 `limit=100`，无分页/无限滚动，游戏量上千后不可用
- 无游戏详情页（卡片直达游戏，无介绍/截图/评分）
- 无新手引导、平台级游戏帮助/规则说明入口
- 无多语言、无平台级音效/通知设置

**运营能力**
- 无推荐位/置顶/大厅排序配置（测试提示词中的运营角色无对应功能承载）
- 无活动配置（签到/礼包/促销）
- 无数据看板（DAU、游戏热度、派奖率、RTP 监控）

**后台能力**
- 无游戏删除/归档清理入口（操作列仅 编辑/版本）
- **无游戏参数配置体系**：RTP、Paytable、Jackpot、Bonus 等全部硬编码在开发商提交的 JS bundle 里，平台无法配置化管理（测试提示词的核心检查项，完全缺失）
- 无配置版本管理/回滚（版本切换仅针对整个包）
- 审计日志页面存在但覆盖面待验证

**资金体系**
- 玩家无充值/提现流程，余额完全依赖管理员调账（生产不可运营）

## 9. 回归缺陷修复记录（N-01 / N-02，2026-08-17）

首轮回归确认 BUG-01~14 全部通过，新发现 2 个 P3 级问题，已修复并复验：

**N-01｜余额不足首次触发时错误文案不精确**
- 现象：引擎余额缓存高于真实余额时（如管理端刚调低），首次 SPIN 错误条显示「回合结算失败」而非「余额不足」；第二次才正确。
- 根因：钱包结算失败的具体原因（`insufficient balance`）未透传给游戏 JS，`endRound()` 只返回 bool，游戏只能报通用文案并覆盖掉更早到达的 `wallet:error` 准确文案。
- 修复：平台层在 `commitRound` 失败时记录真实原因，新增 `platform.lastRoundError()` 注入 goja（beginRound 时清空）；示例游戏在 `!roundCommitted` 分支优先透传该原因（旧平台版本回退通用文案）。backend-sdk 接口声明与 README 同步更新。
- 复验：✅ 会话内调账 990→5 后首次 SPIN 即显示「余额不足，请充值或降低下注金额」，且余额显示同步为 5，流水无扣款记录。

**N-02｜管理端调账后引擎缓存陈旧导致下一次 SPIN 误判**
- 现象：调账 5→1000 后（宿主推送显示 1000），SPIN 报「余额不足」（引擎缓存仍是 5），再 SPIN 一次才自愈。
- 根因：游戏侧余额预检查读的是引擎缓存快照，与钱包权威余额存在双源不一致；调账不失效引擎缓存。
- 修复：删除示例游戏引擎侧余额预检查，钱包成为扣款/拒绝的单一裁决方（本就具备余额不足防线）；引擎缓存仅用于展示（会话初始化、`balance:query`），显示侧由宿主 15s 轮询推送保持权威。
- 复验：✅ 会话内调账 5→1000 后立即 SPIN 直接成功（余额 990），无虚假报错；流水 `-10 → 990` 正确。

验证环境：游戏包已升级至 **1.0.6**（pkg id=7），game-api 含 `lastRoundError` 支持重启生效。回归测试数据：`playertom` 余额已恢复 980。
